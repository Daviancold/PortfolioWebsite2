## Overview

This project is done under a module in NUS called CS3219 (Software Engineering and Principles). It is a collaborative, microservice-based platform designed to help students and aspiring software engineers prepare for technical intervies. 
The platform allows users to simulate real-world coding interview scenarios by matching them with peers to solve technical problems in a shared, real-time environment. The project allowed us to explore the use of event-driven communications, 
as well as learn to implement software using a microservices architecture.

## Key Features

- **User Matchmaking**: Pairs users based on selected criteria such as question difficulty (easy, medium, hard), topic of interest, and proficiency level.
- **Live Collaborative Code Editing**: Provides a shared coding environment where matched peers can work together on solutions with real-time synchronization of code, cursor positions, and highlights.
- **Real-time Chat**: Features a text-based chat service within the collaboration space to facilitate direct communication between participants.
- **Code Execution**: Integrated with JudgeZero to allow users to execute their code in a secure, sandboxed environment and view results instantly.
- **Session Management**: Allows users to terminate sessions smoothly or view past attempts in a dedicated "view-only" mode that preserves the integrity of previous work.

## Technologies Used

- **Next.js and TailwindCSS**: For fast, server-rendered React applications with modern, accessible UI.
- **TypeScript**: For static type checking, improving code clarity and reducing runtime errors.
- **Node.js and Express.js**: For bootstrapping the various backend microservices.
- **WebSockets**: For real-time features such as live editing, chatting and cursor synchronisation.
- **RabbitMQ**: For handling matchmaking logic.
- **MongoDB and Mongoose**: For storage of all structured data for users, questions and sessions.
- **Docker and Nginx**: For service containerisation and enabling of reverse proxy for all services.

## Challenges and Learnings

One of the biggest challenges was attempting horizontal scaling for our services. While the modular approach improved separation of concerns, initial planning deficiencies led to tighter coupling between 
services than intended, hindering independent scalability. Due to tight sprint deadlines, we had to prioritized core functionality over infrastructure optimization. A key takeaway was the need for a 
more robust architectural design, specifically decoupling the queuing mechanisms from the services and implementing data hashing to allow services to scale independently and handle high-concurrency workloads more effectively.

## Outcome

The project was successfully completed with a working design that fitted the user requirements we initally sought to fulfil, leveraging technologies such as continuous deployment using Github Actions to 
Netlify and DigitalOcean. The final platform also achieves high performance through server-side rendering and efficient real-time synchronisation, meeting the complex requirements of this project.
